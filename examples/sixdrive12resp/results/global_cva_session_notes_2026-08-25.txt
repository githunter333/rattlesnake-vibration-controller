2. WHY CVA PEAKS READ LOW VS GROUND TRUTH
===============================================================================
Visual review of global_cva_frf_validation.png and global_cva_frf_pairs.png
showed a consistent pattern: CVA tracks the true FRF closely everywhere
(mode frequencies, anti-resonance dips, off-resonance shape) EXCEPT at the
tops of resonance peaks, which consistently read a bit low vs ground truth.
Frequency locations are essentially exact; it's specifically peak HEIGHT
that's biased.

2.1 Hypothesis (reasoned from the method, before running anything new):
identified poles are systematically slightly more damped than true. Peak
height for a lightly-damped mode goes roughly as 1/zeta, so even a small
zeta bias produces a visibly flattened peak while leaving frequency, phase,
and off-resonance regions untouched. Candidate mechanisms:
  (a) ERRORS-IN-VARIABLES SHRINKAGE: the state sequence Xk used to fit A is
      itself an estimate (J @ P, from a finite record), not the true state.
      Regressing Xk+1 on a noisy Xk is a classic errors-in-variables
      problem, and it biases fitted eigenvalues toward the origin (i.e.
      toward more apparent damping). This is well documented for
      subspace/N4SID-family methods generally.
  (b) C/D COLLINEARITY: C and D are fit jointly in one lstsq against
      [Xk, u_k]. Xk is built from delayed y,u including samples adjacent to
      the current u_k, so some resonant energy could get explained by the
      flat, non-resonant D term instead of by C(zI-A)^-1B, which would also
      read as "peaks low, everything else fine."
  (c) rank/lags truncation.

2.2 Empirical test (globalcva/check_damping_bias.py): rebuilt the exact
physical state-space SDynPySystemAcquisition._build_state_space builds
(components/sdynpy_system_virtual_hardware.py), directly from the raw
mass/damping/stiffness/transformation/coordinate arrays in
sdynpy_frame6x12_system.npz -- this sidesteps importing components/, which
pulls in the full Qt GUI stack (components/__init__.py imports Ui,
environments, acquisition, output, streaming -- the whole Rattlesnake app;
not worth headless-shimming for a diagnostic script). Sanity check: this
hand-built continuous-time H(f) matches the saved ground-truth
frf_frame6x12_H.npz to rel_err = 0.0000, so the reproduction is exact, not
an approximation. Bonus: this system's damping is EXACTLY proportional
(Phi.T @ C @ Phi is diagonal to numerical precision), so the true per-mode
zeta pulled from eigh(K,M) + modal projection of C is exact ground truth,
not itself an estimate.

Result at 1s / lags=40 / rank=66 (the validated config): of 33 true modes
in-band, CVA resolved 32 distinct poles. Matching each true mode to its
nearest identified pole:
    median zeta_id/zeta_true = 1.078   mean = 1.161   76% of modes over-damped

This confirms hypothesis (a)/(b) directly -- most modes read ~5-15% more
damped than true. But the biggest outliers were not generic bias: they were
CLOSELY-SPACED MODE PAIRS that collapse onto a single identified pole. True
modes at 412.66/413.61 Hz (0.95 Hz apart), 451.00/454.74 Hz (3.7 Hz apart),
and 718.25/728.20 Hz (10 Hz apart) each get ONE identified pole, and that
merged pole's damping has to broaden to explain both resonances at once --
the mode near 438 Hz showed zeta_id/zeta_true = 3.0, and 788 Hz showed 1.87.
So there are two stacked effects: a broad ~10% shrinkage bias on essentially
every mode, plus a much larger, localized effect wherever two true modes sit
closer together than the record's frequency resolution (~1/duration) can
separate -- see section 4 for how this responds (or doesn't) to rank/lags.

Full per-mode table is reproducible via: python3 globalcva/check_damping_bias.py

4.4 Close-pair resolution vs rank/lags: tracked, for the 4 true-mode pairs
<5 Hz apart in-band (246.94/249.18, 412.66/413.61, 451.00/454.74,
821.75/824.72 Hz), how many resolve into two DISTINCT identified poles
rather than collapsing onto one. Result: no clean monotonic trend against
either rank or lags -- bounced between 0/4 and 3/4 across the whole sweep
with no obvious pattern. The one lever that consistently helped was
DURATION (part A): 1/4 resolved at 0.5s vs 2/4 at both 2s and 4s. This
supports reading the close-pair failure as closer to a fundamental
frequency-resolution limit (~1/duration -- at 1s that's ~1 Hz, right at the
edge of the 0.95 Hz-apart pair) than as something rank or lags alone fixes.

4.5 CONCLUSION / VALIDATED DEFAULTS: keep LAGS=40, RANK=66. rank=66 sits
right at a sharp real threshold (not padding room needed above it); lags=40
is near-optimal and larger values actively hurt. The rank=None auto
heuristic is safe to use unattended (matches forced-rank=66 performance
within a few percent at every duration tested) but is not slack -- it picks
values close to the rank<=58 collapse zone, so don't assume it would
gracefully degrade on a system where the true order is less certain than
here. global_cva_frf.py's module docstring has been updated with this
validation summary (previously it only reported the H1-comparison numbers).
Reproducible via: python3 globalcva/sweep_rank_lags.py [A|B|C]

8. NOISE INJECTION SWEEP (globalcva/noise_injection_sweep.py)
===============================================================================
Motivated by a design question raised mid-session: many CVA formulations
include an explicit stochastic/innovations term --
    x(k+1) = A x(k) + B u(k) + K e(k)
    y(k)   = C x(k) + D u(k) + e(k)
-- which global_cva_v2 omits entirely (pure deterministic output-error fit).
The existing validation is noise-free, so that omission costs nothing there.
This sweep adds additive white measurement noise to the response (per
output channel, std = noise_frac * that channel's own RMS, since channel
amplitudes span ~2 orders of magnitude -- see global_cva_frf_pairs.png) and
re-runs both CVA (lags=40, rank=66) and H1 across noise_frac in
[0, 0.02, 0.05, 0.1, 0.2, 0.5] at durations [0.5, 1, 2, 4]s.

RESULT -- decisive, not marginal: the zero-noise CVA-vs-H1 advantage that
motivates this whole line of work collapses almost immediately under noise,
not gradually.

  duration=1.0s
    noise_frac   CVA rel_err  zeta_bias  n_modes | H1 rel_err
        0.00         0.1408      1.078      32   |    0.1970
        0.02         0.2369      1.149      29   |    0.1975   <- H1 already wins
        0.05         0.2478      1.289      28   |    0.2003
        0.10         0.2555      1.250      27   |    0.2099
        0.20         0.2842      1.266      27   |    0.2407
        0.50         0.3441      1.461      24   |    0.4006

  duration=2.0s
    0.00  0.0979  1.049  32 | 0.1263
    0.02  0.1493  1.098  31 | 0.1265   <- H1 already wins
    0.05  0.1621  1.160  30 | 0.1274
    0.10  0.1722  1.212  28 | 0.1309
    0.20  0.1950  1.241  27 | 0.1447
    0.50  0.2534  1.415  25 | 0.2194

  duration=4.0s: same pattern, H1 already ahead by noise_frac=0.02
    (0.1116 CVA vs 0.1008 H1).

  duration=0.5s is the one exception: CVA keeps an edge across the whole
  noise range (0.50 vs H1's 0.65 at the top), but the huge zero-noise
  advantage (0.23 vs 0.56, 2.4x better) craters to a much smaller one
  (0.41 vs 0.56, 1.4x) at the very first noise step, then plateaus --
  most of the damage happens between 0% and 2% noise, same as the other
  durations, it just doesn't fully cross over because H1 is already so
  poor at 0.5s.

zeta_bias climbs monotonically with noise at every duration (e.g. 1s:
1.078 -> 1.461 from 0% to 50%), and n_modes recovered drops (32 -> 24) --
i.e. measurement noise directly compounds the SAME over-damping/pole-
shrinkage bias characterized in section 2, via the same mechanism
(regressing A on an increasingly noisy estimated state Xk). This is not a
new, separate failure mode -- noise makes the existing one worse.

CONCLUSION: the explicit error/innovations term is worth building, and this
is no longer a theoretical argument -- it's demonstrated. The deterministic
-only formulation's core selling point (2-4x less data than H1) is a
noise-free-only result. At durations >=1s, H1 already matches or beats CVA
at just 2% RMS sensor noise, well before real accelerometer/shaker noise
floors would plausibly land. This directly de-risks handoff item 4 (never
run live on Rattlesnake) -- running the current deterministic model against
a real .nc4 record would very likely underperform H1, not beat it.

Plot: examples/sixdrive12resp/results/global_cva_noise_injection_sweep.png
Reproducible via: python3 globalcva/noise_injection_sweep.py

Suggested next step (updates section 6): before running against a real
.nc4 record (old item 2), implement the innovations-form extension (K e(k)
term) and re-run this exact noise sweep against it, to quantify how much
of this collapse it recovers. The unused Vgt (future-side canonical

9. INNOVATIONS-FORM REBUILD (globalcva/global_cva_innovations, in global_cva_frf.py)
===============================================================================
Direct follow-on to section 8's finding and the mid-session design question:
does adding the explicit error/innovations term many CVA formulations use
(x(k+1)=Ax+Bu+Ke(k), y(k)=Cx+Du+e(k)) help? Implemented as a new function,
global_cva_innovations(), appended to global_cva_frf.py (global_cva_v2 is
untouched -- still the validated deterministic baseline; v2's return dict
gained one new key, Xkp1, needed by the new function, which is additive and
doesn't change v2's existing behavior for any caller).

9.1 SCOPING DECISION: this does NOT re-derive N4SID's oblique-projection
state-extraction theory (the textbook mechanism that gives subspace ID
proven consistency under noise). That would mean changing how Xk itself is
built, a bigger and riskier rewrite. Instead it keeps global_cva_v2's
Xk = J @ P exactly as validated, and adds a standard two-stage
"subspace init + Kalman refinement" scheme:
  1. Run global_cva_v2 once for an initial A,B,C,D and state sequence Xk.
  2. Compute that fit's residuals -- w_k (process) and e_k (the
     innovation) -- and their sample covariances Q, R, S.
  3. Solve the filter-form discrete algebraic Riccati equation (via
     scipy.linalg.solve_discrete_are, using the standard control<->filter
     DARE duality: solve_discrete_are(A.T, C.T, Q, R, s=S)) for the
     steady-state Kalman gain K.
  4. Run the resulting steady-state Kalman filter FORWARD through the
     actual (y,u) data, warm-started from Xk[0], to get a filtered state
     x_hat(k) -- a minimum-variance estimate GIVEN the model, which
     down-weights noisy samples via K rather than treating every raw
     sample equally the way the static projection Xk=J@P does.
  5. Re-fit A,B,C,D on x_hat instead of Xk (same lstsq machinery as v2),
     and repeat 2-4 for refine_iters rounds.
Note explicitly: computing K alone (refine_iters=0) changes NOTHING about
the deterministic transfer function C(zI-A)^-1B+D -- K only describes the
noise-to-state path. All of the improvement below comes from the
refinement loop actually re-fitting on the Kalman-filtered state.

9.2 CORRECTNESS CHECKS (all passed):
  - refine_iters=0 gives A,B,C,D bit-identical to global_cva_v2 -- confirms
    the "K alone changes nothing" claim above is actually true in code,
    not just in the docstring.
  - The closed-loop filter A-KC is Schur stable (max|eig|=0.953<1) on the
    first test case -- a real correctness check on the DARE solve/gain
    formula, not just "it ran without erroring."
  - P (the Riccati solution) is PSD to numerical precision.
  - Convergence: refine_iters=1,2,3,5,8 give IDENTICAL rel_err in every
    case tested (noise-free and noisy) -- one refinement pass reaches a
    stable fixed point, more iterations buy nothing. refine_iters=1 is the
    practical default.
  - In the full noise sweep below (24 duration x noise_frac combinations),
    the refined filter was Schur-stable in every single case -- no
    divergence encountered.

9.3 RESULT -- improves BOTH the noise-free baseline AND noise robustness,
substantially. Repeated the exact noise/duration grid from section 8
(globalcva/noise_injection_compare_innovations.py), now three-way:
CVA-deterministic (v2) vs CVA-innovations (1 refine) vs H1.

     0.02    0.2369     0.1477     0.1975   <- det already lost to H1 (sec 8); innov still well ahead
     0.05    0.2478     0.1602     0.2003
     0.10    0.2555     0.1846     0.2099

     0.50    0.3441     0.3069     0.4006   <- innov beats H1 at EVERY level tested, 0-50%
