1. RUN 30 -- THE LIVE FRF ESTIMATE DIVERGED, AND THE LAW COULD NOT GET OUT
===============================================================================
Not a solver problem.  The class's own diagnostic:

    H drift on refined bins: since_initial[median=39834.0460, max=500217.6528]

The live H1 estimate was four to five orders of magnitude away from the system
identification, and the law solved against it: 1.8e5 V commanded, 176 solver failures.

The demotion gate WORKED -- 69% demoted over the first 75 calls, max movement 209366 --
which is the lesson: falling back to the safe solver does not help when the plant MODEL is
garbage.  Both solvers get the same bad H.  The gate protects against solver fragility,
not estimator divergence.

Then the end state, calls 109-182: every scheduler field zero, self-prediction bit-identical
for seventy consecutive calls.  An ABSORBING STATE --

    corrupted H -> near-zero drive (0.0015 V) -> no excitation -> live FRF stops moving
    -> nothing trips frf_update_threshold -> no bins scheduled -> same dead solution

It cannot recover, because recovering requires excitation the law is no longer commanding.
The process was killed by the user; nothing crashed, and there were no errors in
Rattlesnake.log at all.

The system ID was NOT the cause and was checked first, given the history of blaming one
wrongly: run 30 median coherence 0.9977, 5th percentile 0.9713, against run 29's 0.9979 /
0.9702.  Comparable.  Channel 7 at 0.424 is normal for this rig.

===============================================================================
2. TWO GUARDS, IN THE BASE CLASS SO BOTH LAWS GET THEM
===============================================================================
GUARD 1, divergence (_reject_diverged_frf).  Per BIN, not global: a bin whose live FRF has
moved more than _FRF_DIVERGENCE_LIMIT (10.0) from the system-ID FRF reverts to its
system-ID value for that call.  One wild line cannot condemn the array, and a bin recovers
by itself when the live estimate comes back.  10.0 against run 28's healthy since_initial
of median 0.1752, max 0.8920 -- an order of magnitude of headroom -- and it catches run 30
at its 55th call.

GUARD 2, deadlock escape (_escape_deadlock_if_starved).  Fires only when the predicted
response has sat _DEADLOCK_ESCAPE_DB (20) below specification WITH NOTHING SCHEDULED for
_DEADLOCK_ESCAPE_CALLS (10) consecutive calls, then discards the live FRF and re-solves
from the system ID.

Neither guard fixes what made the estimate diverge.  They stop the law amplifying it.
