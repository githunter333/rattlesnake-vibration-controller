Control laws in the Rattlesnake MIMO random environment

Algorithms, equations and flow charts · 6-12-8 system · 13 September 2026 · control_laws/

Five subjects: the four control laws compared on hardware, plus the achievable-response predictor that supplies the denominator every comparison is measured against. Each section gives the algorithm, the governing equations, a flow chart, the parameter string, and what was actually measured.

0. Common interface and notation

Rattlesnake loads a control law by explicit path with importlib.util.spec_from_file_location — there is no package context, so a law cannot use relative imports. A law is either a plain function called once per control cycle, a generator, or a class constructed at INITIALIZE_PARAMETERS (before system ID) whose control() is then called each cycle. The profile names the script, the function, and the parameter string; the function type is inferred from the module.

Every law returns the same object: the commanded drive CPSD.

N  drives (6 here)   M  control channels (8)   F  frequency lines (901 in band)

H(f)   M × N  frequency response function
X(f)   N × N  drive CPSD — what the law returns; must be ⪰ 0
Gxx(f)  M × M  specification CPSD (diagonal here)
Y(f) = H X HH  predicted response CPSD
ym = diag(Y)m   the auto-spectra that are actually specified and scored
The constraint that shapes every law. X must be a valid cross-spectral matrix, i.e. positive semidefinite. The set of achievable response auto-spectra is therefore D = { diag(H X HH) : X ≽ 0 }, the image of the PSD cone under a linear map. When M > N — eight control channels from six shakers — D is a proper subset of the positive orthant, so a perfectly reasonable flat specification can be partly unreachable. No law gets outside D. How each law respects positive semidefiniteness is the main thing that distinguishes them.

1. match_trace_pseudoinverse function · control_laws.py

The baseline, and the only law in the set with a long validation history. One open-loop pseudoinverse solve at startup, then a single real scalar per frequency line for the rest of the test.

Algorithm

first call — open loop
H+ = pinv(H, rcond)
X = H+ Gxx (H+)H
s = min(1, 10cap/10 · tr(Gxx) / tr(H X HH))  startup guard
X ← s · X

every call after that — closed loop on total power only
c(f) = tr(Gxx(f)) / tr(Gyy(f))
X(f) ← c(f) · Xprev(f)

The update is, in log-power terms, a pure discrete integrator with gain 1 on the log-power error: writing e(k) = log tr(Gxx) − log tr(Gyy(k)), the update is exactly log X(k) = log X(k−1) + e(k−1). There is no proportional term, and the error it integrates arrives through whatever CPSD averaging is configured — a pure integrator fed a lagged error, which is the classic slow-to-settle, overshoot-prone configuration. Simulation at averaging coefficient 0.10 gave ~53 cycles and ~103 % peak overshoot to settle within 5 %.

Why it is safe: a uniform positive real scalar can never turn a valid drive CPSD into an invalid one, and after startup the FRF is never inverted again. Why it is limited: if channel 3 is 5 dB high and channel 5 is 5 dB low, the trace is correct and the law does nothing at all.

2. optimal_diagonal_control class · optimal_diagonal_control.py

Chooses the drive CPSD's cross-terms to minimise diagonal error directly, rather than fixing them from an independent-drive survey. Per frequency line it solves a genuine semidefinite program.

The per-bin SDP

minimizeX  ‖ diag(H X HH) − ytarget ‖² + reg · ‖X‖²F
subject to  X ⪰ 0
           |Xij| ≤ ρ · √(Xii Xjj)  for all i ≠ j

Both constraints are convex — the coherence one is |affine| ≤ concave — so this is a true convex program with no manifold optimisation, solved with CLARABEL and warm-started between calls.

The budgeted scheduler

Solving every line up front costs seconds. Instead the law runs a five-step schedule per call, spending a fixed budget of max_bins_per_update SDP solves where they do most good, so control can begin on iteration 1 with a full-spectrum result:

  1. Instant baseline. Every bin gets Rattlesnake's closed-form buzz solve — H+ synthesis with cross-terms from a survey if available, zero if not. Effectively free.
  2. Targeted refinement. The worst-predicted-error bins above error_threshold_db get the full SDP, replacing their buzz solution.
  3. Progressive. Repeats every call, chipping away until the band is refined or good enough.
  4. FRF drift. Already-refined bins whose H has moved past frf_update_threshold are re-solved with priority, capped at half the budget so they cannot starve step 2.
  5. Stale re-triage. Leftover budget re-checks already-refined bins against the current H rather than H-drift magnitude — without this, once every bin is refined, step 2 never runs again and a degrading bin is orphaned on its stale solution forever.
The coherence cap reaches only SDP-refined bins. The buzz baseline is left uncapped on purpose — it draws its cross-terms from an independent-drive survey, so it has no dependent-drive problem to begin with. With max_bins_per_update = 20 across 901 lines, most bins carry the uncapped baseline. This is the most likely explanation for the measured null result: turning the cap off changed the overall error by 0.008 dB.

3. optimal_diagonal_control_fast subclass · optimal_diagonal_control_fast.py

Identical baseline and scheduler, inherited unchanged. The only override is how a single bin is solved: the SDP is replaced by an unconstrained Burer-Monteiro factored solve whenever that is safe.

X = L LH,  L ∈ ℂN×r,  r = bm_rank

minimizeL  ‖ diag(H L LH HH) − y ‖² + reg‖X‖²F
∇X = 2 HH (resid ⊙ H) + 2·reg·X   ∇L = 2 ∇X L
L-BFGS-B, analytic gradient, maxiter 50

Factoring X as L LH makes positive semidefiniteness structural — the parametrisation is unconstrained, so no cone projection is needed and the solve is far cheaper. Benchmarked at a 12-drive/30-response scale: SDP ~105–119 ms/bin against ~5.4–5.7 ms/bin for the factored solve, roughly 18–20× faster, matching SDP accuracy to a mean of −0.02 dB.

The safety rule, and why it disabled the fast path here. Left unconstrained, the factored solve drives pairwise drive coherence to exactly 1.0 in essentially every bin — perfectly rank-deficient drives, which would make a live H1 estimator's reference CPSD matrix singular. Rather than trying to detect the "Update Transfer Function During Control" setting, which the call signature does not expose, the law watches the safety-relevant property directly: has H changed since the last call? If it has, every solve for the rest of that call uses the safe capped SDP instead. In this study FRF update was on, so H changed every call and the fast path never engaged — runs 05 and 06 are repeats of 03 and 04.

Parameters

The same five as optimal_diagonal_control, plus:

6bm_rank4 Factorisation rank r. With M = 8 the threshold below which spurious local minima generically appear is √(2M) ≈ 4, so the default sits exactly on it; 6 was used in this study.

4. match_diagonal_congruence class · diagonal_congruence_control.py

Generalises match_trace from one scalar to N independent knobs, while keeping the structural property that makes match_trace safe.

The generalisation

match_trace:  X ← c · X   (one real scalar)
this law:     X ← D X D,  D = diag(eu₁ … euN), u real

A diagonal congruence preserves positive semidefiniteness structurally: if X ⪰ 0 then D X D ⪰ 0 for any real diagonal D. So exactly as with match_trace, no choice of gains — however wrong the FRF, however noisy the measurement — can command a physically invalid drive. match_trace is the special case D = √c · I.

Choosing the gains

ym = (H X HH)mm  predicted response
Smi = ∂ log(ym) / ∂ui = 2 Re( Hmi (X HH)im ) / ym
εm = log( targetm / achievedm )  measured log error

u = argmin ‖ S u − ε ‖² + λ‖u‖²,  λ = ridge · tr(STS)/N
one Gauss-Newton step on the log-domain problem, restricted to diagonal congruence

Every row of S sums to exactly 2, because scaling all gains together by t scales X by e2t and hence y by e2t. The consequence is that when the error is the same on every channel, the solution is ui = ε/2 for all i — the law reproduces match_trace's update exactly. It degrades gracefully to the law it generalises.

max_step_db bounds the response, not the gains. An early version clamped u directly, which does not bound the outcome: rows of S sum to 2 but individual entries can be large and opposite-signed, so a 3 dB clamp on u produced a 38 dB swing in response. The clamp is now enforced on the exact predicted per-channel response move, iteratively, up to six passes.

5. achievable_response not a control law · achievable_response.py

The pseudo control law. It drives no hardware. Given an FRF it answers the question every comparison needs a denominator for: how much of my response error is the control law's fault, and how much is simply not reachable with this structure and these shakers?

per frequency line, over X ⪰ 0:

best_rms_db     min √( meanm (10 log₁₀(am/ym))² )
best_minimax_db  min maxm |10 log₁₀(am/ym)|  the honest ± X dB floor
achieved        the am = diag(H X HH) that attains it
drive_trace     tr(X) required — feasibility against real shaker limits

Solved by the same Burer-Monteiro factorisation the fast law uses, X = L LH, but minimising the residual in the dB domain rather than the linear one — dB error is the quantity a vibration test is judged by, and a linear residual over-weights loud channels. The Jacobian is built with Wirtinger calculus:

dm = log(am) − log(ym)  residual
∂am/∂L̄ = conj(hm) ⊗ rm / am
J = [ Re(G) | Im(G) ]  real and imaginary blocks, 2NK columns
least_squares(method='trf') — not 'lm', which refuses m < n

Each law solves the same problem with a different guarantee of validity, and that choice is what determines both its power and its limits:

Results are the cap-on runs from the 12 September comparison, linear plant, against the flat specification. Scored instead against what is achievable, congruence leads at 3.49 dB against optimal_diagonal's 4.00 dB.

Open defects. Neither optimal-diagonal law has a startup level cap — match_trace and congruence both take startup_test_level_cap_db, but the optimal-diagonal laws solve against the full specification and command it immediately. The fast law's central claim, that Burer-Monteiro at rank 6 matches the SDP, remains untested on this system because FRF update disabled its fast path.
